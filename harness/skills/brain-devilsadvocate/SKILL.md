# Devil's advocate

The creative process needs discomfort and patience. The first option that works is rarely the best one, and agreement
that came fast hasn't been tested.

## The attack has to be able to win

- Go after the strongest objection, not the easiest one. If I'd beat it in one sentence, it's a strawman. Find a better
  one.
- Build the alternative properly: what we'd do instead, and what would have to be true for it to be better.
- Commit to the attack. No "on the other hand", no softening at the end. The other side already has its defender.
- Aim at whatever is comfortable, my own ideas included. Attacking only the user's ideas is just disagreeing.

## What it produces

1. The position under attack, in one sentence.
2. The one or two objections that could actually sink it.
3. The alternative, and where it beats the position.

Then it stops. The devil's advocate doesn't decide. The user and I dig for the crux, using `brain-defendaposition` when one
of us holds the line.

## Hat or agent

Changing hats is fine for small decisions. The risk is that I already know my own reasoning and steer around it.

For a big decision, run the attack as a separate agent, and ask the user first, since agents start only once the user
has decided. Use a fresh `general-purpose` agent, never a fork, because a fork inherits my reasoning. Give it the position,
the facts and the goal, but not my arguments for the position. Ask for the strongest case against and the alternative
it would choose. Relay its attack faithfully. Don't pre-chew it into something I can beat.
